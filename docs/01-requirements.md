# 01. 要求定義

## 1. プロダクトの定義

**OpenDraft** は、汎用 2D/3D CAD 基盤（AutoCAD 相当）と、その上に載る建築設備ドメイン層（Tfas 相当）からなるオープンソース CAD である。

### 満たすべき一文

> 協力会社の誰もがコスト障壁なくインストールでき、属性を落とさずに図面と設備モデルをやり取りできること。

これは調査で判明した既存商用製品の実運用課題（バージョン不一致、変換時の属性欠落、下請けへのライセンス費用負担）への直接の回答であり、OSS でなければ実現できない価値である。**「AutoCAD の全機能を再現すること」は目的ではない。**

### 非目標（明確にやらないこと）

- AutoCAD のコマンド体系・UI の完全再現（主要 200 コマンドの互換までとする）
- 機械 CAD 向けの高度なサーフェスモデリング、CAM、解析（FEM/CFD）
- 構造解析・エネルギーシミュレーション本体（外部ツールへのデータ提供に留める）
- 独自の B-rep カーネルの開発
- DWG の完全互換書き出し（r2000 互換書き出し + DXF を主経路とする）

## 2. ペルソナと主要ユースケース

| ID | ペルソナ | 状況 | 中核ニーズ |
|----|---------|------|-----------|
| P1 | 設備施工図オペレータ | サブコン。1 日中ダクト・配管の施工図を描く | 作図速度。キーボード主体の操作。既存 DWG/Tfas 図面が開けること |
| P2 | 設備設計者 | 設計事務所。基本設計〜実施設計 | 系統管理、機器表と図面の連動、風量・流量の計算 |
| P3 | BIM コーディネータ | ゼネコン。統合モデルで干渉チェック | IFC の入出力品質、属性の保全、共通データ環境（CDE）連携 |
| P4 | 土木・建築の一般作図者 | 公共案件 | SXF(SFC/P21) 電子納品、レイヤ名規約の遵守 |
| P5 | 開発者・インテグレータ | 自社ワークフローへ CAD を埋め込む | スクリプト API、ヘッドレス実行、プラグイン |

### 中核ユースケース（優先度順）

1. **UC-1** 既存 DWG/DXF の建築図を背景として読み込み、その上に設備の施工図を描く
2. **UC-2** ダクト・配管のルートを 2D で引き、自動生成された 3D を断面・アイソメで確認する
3. **UC-3** 建築図が更新されたとき、設備図を作り直さずに背景だけ差し替える（シート／外部参照）
4. **UC-4** 統合モデルで干渉チェックを行い、指摘を図面上のマークアップとして共有する
5. **UC-5** 図面から材料・数量を拾い出し、表として書き出す
6. **UC-6** IFC で出す・受け取る。属性が往復して壊れないこと
7. **UC-7** SXF で電子納品する
8. **UC-8** 同じ図面を複数人が同時に開いて編集する

| F-004 | モデル空間 / ペーパー空間（レイアウト）、ビューポート、印刷スタイル |
| F-005 | 外部参照（XREF）: アタッチ / オーバーレイ、パス解決、ネスト、リロード |
| F-006 | オブジェクトスナップ（端点・中点・中心・交点・垂線・接線・近傍・延長・平行）、極トラッキング、直交モード、グリッド、スナップ |
| F-007 | コマンドライン入力（エイリアス、動的入力、コマンド履歴）、コマンドのキャンセル / 繰り返し |
| F-008 | 選択（窓・交差窓・投げ縄・フェンス・前回・全て）、クイックプロパティ、グリップ編集 |

### 3.2 レイヤ 1: MEP ドメイン（Tfas 相当）

| ID | 要件 |
|----|------|
| F-101 | ルート作図: 芯線を引くとダクト/配管が生成され、**同時に 3D 形状が確定する** |
| F-102 | 断面仕様: 矩形/丸/オーバル ダクト、各種管種（鋼管・塩ビ・銅・ステンレス）、保温厚、勾配 |
| F-103 | 継手の自動生成: エルボ、チーズ、レデューサ、フランジ、曲げ半径・角度規則の材種別ルール |
| F-104 | 機器と接続口（ポート）: 機器を置くとポートが定義され、ルートがポートに自動接続・追従する |
| F-105 | 系統（システム）管理: 給水/給湯/排水/通気/冷温水/冷媒/給気/排気/外気/電灯/動力/弱電。系統ごとの色・線種・命名規則 |
| F-106 | 表示モード切替: 単線 ⇔ 複線 ⇔ 3D。同一データの別ビューとして無損失に切り替わる |

| F-108 | 干渉チェック: 設備間、設備 vs 建築（梁・スラブ・壁）、クリアランス（保温・作業空間）を含む。結果を課題として登録・追跡 |
| F-109 | 計算: 風量からのダクトサイズ/ダンパー自動決定、圧力損失、流量からの管径選定 |
| F-110 | 電気設備: 器具の個別/範囲/円弧配置、自動配線、盤・回路の管理、条数・電線種別の集計 |
| F-111 | 拾い出し・積算: 部材の長さ・個数を系統別/階別/工種別に集計し CSV/XLSX へ |
| F-112 | 部品ライブラリ: メーカー部品のカタログ管理、バージョン管理、社内標準部品の配布 |
| F-113 | シート機能: 建築図と設備図を別レイヤ群として分離保持し、建築側の差し替えで設備図が壊れない |
| F-114 | 平面 ⇔ 断面の連動生成（切断線を置くと断面が生成され、双方向に編集が伝播する） |

## 4. 非機能要件

| ID | 項目 | 目標値 |
|----|------|--------|
| N-01 | 描画性能 | 100 万エンティティの 2D 図面をパン・ズームで **60 fps**。初回表示 3 秒以内 |
| N-02 | 3D 性能 | 500 万三角形の設備モデルを 30 fps 以上でナビゲート |
| N-03 | 起動時間 | コールドスタート 3 秒以内（デスクトップ） |
| N-04 | ファイル互換 | 旧バージョンで保存した図面を新バージョンが必ず開ける。新バージョンの図面も**既知の範囲で**旧バージョンが開ける（未知要素は保持して再保存する） |
| N-05 | 数値精度 | 内部座標は f64。図面座標系で ±10^9 mm の範囲を扱い、相対誤差 1e-9 以内 |
| N-06 | 堅牢性 | クラッシュ時に最大 30 秒分の作業のみ喪失（操作ログの継続書き込み） |
| N-07 | 対応 OS | Windows 10/11、macOS 13+、Linux（主要ディストロ）、ブラウザ（WebGPU 対応版） |
| N-08 | 国際化 | UI と図面内容の多言語対応。日本語（縦書き・組版・JIS 製図規則）を第一級で扱う |
| N-09 | アクセシビリティ | キーボードのみで主要操作が完結すること |
| N-10 | ライセンス | コアは寛容型（Apache-2.0）。コピーレフト依存はプロセス境界で隔離 |

### 特記: 日本語・国内規格対応

商用の海外 CAD で不足しがちで、国内採用の可否を決める部分。

- JIS Z 8310 系の製図規則、寸法・公差表記
- 縦書きテキスト、文字間・行間、和文フォント（IPA / Noto）の埋め込み
- SXF レイヤ名規約（電子納品要領）の検査
- 通り芯・階（レベル）の第一級モデル化
- 尺（尺貫法）併記、和暦
